# Debezium 3.6 RPS Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce and validate a selective `3.6.2-yyyymmdd.Final` RPS
Debezium runtime that preserves every approved customization while unchanged
components remain on official `3.6.2.Final`.

**Architecture:** Start from the released `v3.6.2.Final` tag in an isolated worktree. Qualify each historical customization by porting its tests first, retain upstream behavior without duplicate patches, and reimplement only missing business behavior against the current 3.6 modules. Treat dependency convergence and state continuation as release gates, not post-release checks.

**Tech Stack:** Java 21, Maven Wrapper, JUnit, AssertJ, ANTLR4, Testcontainers, Kafka Schema History, Debezium Embedded Engine, MySQL, MariaDB, GoldenDB/TDSQL, Oracle LogMiner.

**Spec:** `docs/superpowers/specs/2026-09-14-debezium-3.6-rps-upgrade-design.md`
